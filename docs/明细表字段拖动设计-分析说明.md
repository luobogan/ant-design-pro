# 明细表字段「单独拖动调整列宽和顺序」— 分析说明

> 任务起点：参考 `D:\Weaver2020\ecology` 中明细表在 Excel 上的设计实现，结合 `http://192.168.1.5:8888/wui/engine.html#/workflowengine/path/pathSet/pathDetail/flowSet/nodeInfo?workflowId=384` 页面中明细表的交互样式，为当前 ant-design-pro 表单建模系统增加「明细表字段可单独拖动调整列宽和顺序」能力。

## 1. ecology 实现梳理（本地代码路径 `D:\Weaver2020\ecology\formmode\exceldesign`）

### 1.1 关键技术栈
- SpreadJS 3.20142.13（`jquery.wijmo.wijspread.3.20142.13_wev8.js`）+ jQuery 1.8 + jQuery UI draggable
- 表单设计器入口：`excelMain.jsp` / `excelOperation.jsp`
- 设计器内核：`designOperate_wev8.js`、`excelBodyOperat_wev8.js`、`excelBaseOperat_wev8.js`、`fieldAttrOperate_wev8.js`、`excelRightClick_wev8.js`、`parseLayout_wev8.js`
- 字段布局存储：SpreadJS 的 SheetArea（`viewport` + `colHeader`），列宽、单元格值、合并等全部由 SpreadJS 对象维护

### 1.2 数据模型
| 表/字段 | 作用 |
|---|---|
| `Workflow_billdetailtable.orderid` | 决定明细表自身的序号（决定左侧"明细表1/明细表2…"） |
| `workflow_billfield.dsporder` | 单个明细表内**字段的列顺序**（excelSetDetail.jsp: `order by t.dsporder`） |
| `Workflow_billdetailtable.detailgroupattr`（拼成 `detailgroupattr<idx>` hidden input） | 明细表的开关集合（增/改/删/复制/默认行数等），与列序/列宽无关 |
| SpreadJS 列宽 `sheet.getColumnWidth(col, viewport)` | 每列的像素宽度，由 `setColumnWidth(col, value, viewport)` 写入；保存到 layout JSON 的 sheet 列定义 |
| `sheet.setValue(row, col, value, ...)` | 单元格值；明细字段占两行：第 1 行=表头（标签文字），第 2 行=表体（Fcontent 占位符） |

### 1.3 关键交互
1. **明细字段的拖入**：右侧面板的 `wfed-drag-Fname`（标签）和 `wfed-drag-Fcontent`（字段），按 `dsporder` 顺序逐列填入；每拖入一个 Fcontent 立即：
   ```js
   // designOperate_wev8.js:2935-2939
   tableBody.find("a[_flag='Fcontent'][_fieldid='"+fieldid+"']").click();
   sheet.setColumnWidth(fieldindex, 120, $.wijmo.wijspread.SheetArea.viewport);
   fieldindex++;
   ```
   列宽 = 120px（每列默认）。
2. **列宽调整**：标准 SpreadJS 三种入口，全部落到 `setColumnWidth(sel.col+y, value, viewport)`：
   - 拖动列头边界（SpreadJS 原生）
   - 选中列→右键菜单「设置列宽」→输入像素值
   - 顶部工具栏「插入」Tab 的列宽按钮（`action === "setcolwidth"` 走 `setRChw("c")`）
3. **列顺序**：**没有自定义 UI**，完全靠 SpreadJS 原生的列头拖动、剪切/粘贴、Ctrl+X/V、MoveRangeCommand 等；明细表内字段顺序的事实源是后端 `dsporder`，拖入即按 `dsporder` 排序。
4. **明细表自身的切换**：`getDetailOrderid(billid)` 走 `excelDetailOrderidAjax.jsp`，返回 `Workflow_billdetailtable.orderid` 列表；右键菜单「切换明细」据此生成 `detail_<orderid>` 子菜单。
5. **明细表属性设置**：点击 `wfed-rightbtn-btn`「明细表属性设置」→ 右侧弹出开关面板（增/改/删/复制/默认行数/合并行等），**不涉及列宽和列序**。

### 1.4 数据流（保存/加载）
- 列宽 → 与单元格值一起存进 SpreadJS 的 sheet JSON（即 layoutJson），不单独入库；
- 列顺序 → 同上；
- 明细表序号 / 明细字段顺序 → 入 `Workflow_billdetailtable.orderid` 与 `workflow_billfield.dsporder`；
- 保存按钮触发 `excelAjaxData.jsp?src=save...`，把 sheet JSON + `detailgroupattr` + 字段布局一起落库。

## 3. 当前系统的差距

| 维度 | ecology | 当前 ant-design-pro |
|---|---|---|
| 设计器内核 | SpreadJS（原生列头拖动、调宽） | Univer（默认也有列边界拖动调宽，列头换序需通过 `move-range` 命令） |
| 明细表数据模型 | `Workflow_billdetailtable.orderid` + `workflow_billfield.dsporder` + SpreadJS 列宽 | `FieldDefinition.detailTable / isMain`（数据已有），但 `layoutData` 不存明细表结构、列顺序、列宽 |
| 字段面板 | 按明细表分组；右键展开明细表选择 | `FieldPalette` 已按 `detailTable` 分组显示（"明细表1 (n)"），与 ecology 一致 |
| 画布渲染 | 明细字段占两行（表头+表体），整列相邻 | 明细字段与主表字段一样，单独成"标签+输入"两格，无明细表区域 |
| 已放置列的操作 | SpreadJS 原生列操作（列头拖、列边拖、右键设宽） | 当前未启用 Univer 的列级交互（拖字段只改单元格内容、不动列结构） |
| 持久化 | SpreadJS sheet JSON + 后端 dsporder | `layoutData.sheets/cellData`，仅存单元格，未存列宽/明细列顺序 |

## 4. 落地方案候选

### 方案 A：在 Excel 画布内构造「明细表区域」
- 当拖入第一个 `detailTable>0` 的字段时，在当前 sheet 下方插入一个明细区块（首行标签、次行字段占位、整列相邻）；
- 列宽：Univer 原生列头边界拖拽；
- 列顺序：给明细表头加上列拖动手柄（封装 `move-range` 命令），可整列移动；
- 持久化：`layoutData.detailTables = [{ tableIdx, name, columns: [{fieldId, width, order, col}] }]`，与现有 `sheets/cellData` 并存。
- **改动最大**，需要新画布组件、列级操作、新的数据结构与序列化。

### 方案 B：保留画布，逐明细表提供「列设置面板」+ Univer 列操作（推荐）
- Excel 画布不动结构；选中明细字段时，右侧 PropertyPanel 增加「明细表列」分区（按 detailTable 分组），每行：
  - 拖拽手柄（@dnd-kit/sortable）可上下调整顺序 → 后台按新顺序调用 `setRangeValue` + `move-range` 真实移动列；
  - 数字输入框调单列宽度 → `sheet.setColumnWidth(col, px)`；
- 首次拖入某明细表的第一个字段时自动生成一个"明细表区块"占位（首行=标签、次行=字段），与 ecology 的两行表保持一致；
- 持久化：`layoutData.detailTables` 同步列顺序与列宽；
- 预览 `ExcelPreview` 增加：识别 `detailTables` 区块并以 AntD Table 渲染多行（带列宽）；
- 与现有「单字段拖入 / 字段置灰 / 撤销重做 / 防篡改回滚」机制可平滑衔接（参见 MEMORY.md 大坑点）。

### 方案 C：纯属性面板模式（最小改动）
- 不动画布列结构；
- PropertyPanel 增加明细表分组，每字段加 `displayOrder` 数字框 + `width` 输入；
- 用户改 `displayOrder` 后，由后端排序 `dsporder` 重绘；
- 列宽不真实落到 Univer，仅记到 layout 元数据，预览时使用；
- 体验较弱：列宽不可视拖拽、换序不直观。

## 5. 推荐方案

**方案 B**。理由：
1. ecology 的实质就是"字段库 + 列级操作 + 后端 dsporder"，方案 B 与之最接近；
2. 避免大改 `UniverExcelGrid` 画布，可逐步叠加：
   - 阶段 1：明细字段拖入即开两行占位 + 列宽持久化 + 列设置面板
   - 阶段 2：明细列拖拽换序（@dnd-kit + Univer `move-range`）
3. 与 MEMORY.md 中诸多坑点（拖动 / 撤销 / 整字段移除 / 防止篡改 / 详情字段双向一致性）均可在现有 hook 之上叠加；
4. 工作量适中（1-2 个工作日），风险可控。

## 6. 验收要点（草案）

1. 拖入同一 `detailTable` 的多个字段 → 画布自动形成明细区块（首行=标签、次行=字段，整列相邻），与 ecology 截图一致；
2. 字段面板按 `detailTable` 分组显示已放置字段，每行可拖拽调顺序，调完后画布列顺序同步刷新；
3. 单列宽度可调，画布列头边界拖动同步生效，宽度持久化到 layout；
4. 删除明细字段 → 整列移除 + 列宽释放（参考现有 `removeFieldCompletely` 的两格释放机制）；
5. 保存/加载 → `layoutData.detailTables` 完整还原列顺序与列宽；
6. ExcelPreview 预览明细表为 AntD Table，按列宽渲染；
7. 撤销/重做 Undo 栈仍生效（Univer 命令级别）；
8. 不影响主表字段的拖放与面板置灰。

## 10. 需求转向：ecology「主表标记 + 子画布」模型（2026-09-05 修订）

用户确认实际要的是 **ecology formmode/exceldesign 原生方式**：主表画布插入可点击的「明细表标记」，点击标记弹出**新的 Excel 画布**编辑该明细表，而非此前第 9 节的「主画布内两行式连续列区块」。第 9 节的 `placeDetailFieldColumn` 两行列方案已**撤销**。

### ecology 关键源码（designOperate_wev8.js）
- `doInsertDetail(action)`：`setCellTextImage(sheet,r,c,"明细表"+n, detailTable_wev8.png)` + `setCellProperties(r+","+c, celltype.DETAIL, {"edetail":action})` → 单元格标记 `etype=7/DETAIL` 带 `edetail="detail_N"`。
- `openDetailWin(edetail)`：校验 `getDetailOrderid` → `new Dialog("excelDesignDetailDialog")` 打开 `excelMain.jsp?isDetail=on&d_identy=detail_N&d_num=...` → **同一个设计器的独立实例**，各自布局缓存 `detail_{N}`。
- 主表 `DETAIL` 单元格 `edetail` 与子画布 `d_identy=detail_N` 一一对应，完成数据关联。

### 本系统落地实现（UniverExcelGrid + ExcelDesign + FieldPalette）
- `FieldMeta.cellType` 新增 `'detailTableMarker'`（携带 `detailTable` 序号）。
- 标记格渲染：`getCellDisplayValue` 返回 `明细表N`；`setCellField` 给标记格上蓝底白字加粗居中样式。
- 新增 `insertDetailMarker(idx)` API：在活动单元格写标记格（同表只插一个），联动 `onLayoutChange` 持久化。
- 选区变化命中标记格 → 通过 `onDetailMarkerOpen(idx)` 回调父组件打开子画布（init effect 用 `onDetailMarkerOpenRef` 避免闭包过期）。
- 主画布拖入 `detailTable>0` 字段 → **不再落格**，改为 `insertDetailMarker` + `onDetailMarkerOpen`（仅主画布；子画布 `isDetailCanvas` 时走普通落位）。
- `ExcelDesign`：
  - 工具栏「插入明细表」`Dropdown`（选项来自 `fieldDefinitionApi.getByFormId` 聚合的 `detailTable` 序号）。
  - `detailLayouts` 状态 + `layoutData.detailTables[idx]` 持久化；主/子布局合并（`handleLayoutChange` 保留 `detailTables`，`getDetailLayoutChange` 写回）。
  - 点击标记/`Dropdown` → `openDetailCanvas`：记下 `mainGridApiRef = window.univerExcelGrid`，打开 `Modal` 承载子 `UniverExcelGrid`（`isDetailCanvas` + `detailTableFilterIdx`）+ 过滤后的 `FieldPalette`；关闭时 `closeDetailCanvas` 恢复 `window.univerExcelGrid` 指向主画布。
  - 因两实例都写 `window.univerExcelGrid`，关闭子画布需恢复主画布 API（否则主画布拖放/属性失效）。
- `FieldPalette` 新增 `detailTableFilter`：仅渲染指定明细表的字段（子画布用）。

### 数据关联 & 布局一致性
- 关联键 = `detailTable` 序号：主标记格 `detailTable=N` ↔ 子画布 `detailLayouts[N]`。
- 列宽/列序在每个画布内由 Univer 原生列宽 + 物理列序维护（沿用既有的 `columnData`/物理列序持久化，无需额外结构）。
- 主布局保存时 `detailTables` 随整体 layoutJson 落库，刷新后 `loadFormLayout` 还原 `detailLayouts`，标记格随主 cellData 还原。
