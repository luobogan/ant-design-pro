## 0. 设计前提与关键结论

1. **用户系统已具备，无需从零新建**
   本项目已有完整的前端用户体系：登录页 `/user/login`、初始态注入 `currentUser`（`getInitialState` → `GET /api/blade-system/user/info`）、`access.ts` 权限判定、头像下拉 `AvatarDropdown`、菜单与按钮权限下发。本模块所谓的"新增前端用户系统"在此解读为：**在已登录用户上下文中，搭建面向用户的流程办理门户（流程中心）**，并复用既有鉴权/路由/权限基础设施，不另起一套。
   > 若你的本意是"新建独立的用户/组织/角色管理后台"，那属于 `System` 模块（项目已有 `src/pages/System/User|Dept|Role|Tenant`），与本流程模块正交，本文聚焦流程办理侧。

2. **后端契约已就绪**
   `src/services/workflow/index.ts`（`WORKFLOW = '/api/blade-workflow'`）已封装：
   - 待办 `listTodo(assignee?)`、已办 `listDone(assignee?)`
   - 发起 `startInstance(dto)`、渲染包 `renderForm(instanceId, taskId, nodeKey)` / `renderFormPreview(defId, formId, nodeKey)`
   - 审批动作 `approveTask / rejectTask / forwardTask / addSignTask / circulateTask / urgeTask`
   - 实例操作 `getInstance / getLogs / withdrawInstance / stopInstance / resumeInstance / cancelInstance`
   - 统计 `monitorCount(assignee?)`
   - 流程定义 `listDefinitions(formId?)`、`getDefinitionFormCondition`
   审批页 `src/pages/FormMode/Approval/ApprovalPage.tsx` 也已实现（E9 风格操作按钮栏 + 字段权限渲染）。
   **本模块主要是把这些契约组装成 4 个用户页面 + 角标/导航联动。**

3. **需后端补充的契约（设计阶段标注）**
   - 我的请求列表：现有 service **没有**"我发起的实例"接口，建议后端新增 `GET /api/blade-workflow/instance/mine`（见 §4.4、§8）。
   - 可发起流程清单：复用 `listDefinitions()`（按 `formType`/`type` 过滤即可），无需新增。

## 2. 模块功能概述

流程中心（用户侧）由 4 个页面组成，共享同一个"审批/查看"承载页（复用现有 `ApprovalPage`）：

| 功能 | 路径（建议） | 组件文件（遵循 `./pages/{Module}/{Page}/{Page}.tsx`） | 核心 API |
|---|---|---|---|
| 新建流程 | `/workflow/center/create` | `src/pages/Workflow/Center/Create.tsx` | `listDefinitions`、`renderFormPreview` / `startInstance` |
| 待办事宜 | `/workflow/todo` | `src/pages/Workflow/Todo/Todo.tsx` | `listTodo(assignee)`、`renderForm`、`approveTask`… |
| 已办事宜 | `/workflow/done` | `src/pages/Workflow/Done/Done.tsx` | `listDone(assignee)`、`getLogs` |
| 我的请求 | `/workflow/my-request` | `src/pages/Workflow/MyRequest/MyRequest.tsx` | `listMyRequests`（待补）、`getLogs`、`withdrawInstance`、`stopInstance` |
| 审批/查看详情（复用） | `/formmode/approval/ApprovalPage`（已存在，`layout:false`） | `src/pages/FormMode/Approval/ApprovalPage.tsx` | `renderForm`、`approveTask`… |

菜单结构（建议挂在"流程中心"父菜单下，由 `blade_menu` 下发）：

```
流程中心
 ├─ 新建流程      code=workflow_create      path=/workflow/center/create
 ├─ 待办事宜      code=workflow_todo        path=/workflow/todo
 ├─ 已办事宜      code=workflow_done        path=/workflow/done
 └─ 我的请求      code=workflow_myrequest   path=/workflow/my-request
```

> 路由注册推荐走**动态菜单**（与现有 `FormMode/WorkflowDesign` 一致）：只需在 `blade_menu` 写入上述记录并授权给角色，前端 `patchClientRoutes` 会自动按 `Func.formatRoutePath` 拼出 `./pages/Workflow/{Center|Todo|Done|MyRequest}/{Create|Todo|Done|MyRequest}.tsx` 并懒加载。若需静态兜底，可在 `config/routes.ts` 的 `/` 下补 4 条 `component` 记录（参考现有 `ApprovalPage` 的静态写法）。

## 3. 页面结构与交互骨架

### 3.1 总体布局
- 4 个页面均位于 ProLayout 内（带左侧菜单、顶栏头像、水印）。
- 顶栏"待办"入口可加红点角标：进入工作台或每次路由变化时调用 `monitorCount(currentUser.userid)` 取待办数，喂给 `AvatarDropdown` 或自定义 `Badge`。
- 列表页统一用 `@ant-design/pro-components` 的 `ProTable`（`request` 入参接 service，配合 `pickPayload`）。

### 3.2 页面职责与跳转
- **新建流程**：流程目录（卡片/列表）→ 选流程 → 打开发起抽屉/新页（复用 `renderFormPreview` 拿到布局与字段权限）→ 填表 → `startInstance` → 成功后 `message.success` 并跳「我的请求」或「待办」。
- **待办事宜**：`ProTable` 展示待办；行操作"办理"→ 新标签页/抽屉打开 `ApprovalPage?instanceId=&taskId=`；"转办/加签/催办"→ 弹窗（`forwardTask`/`addSignTask`/`urgeTask`）；"流程"→ 打开流程图/日志 `getLogs`。
- **已办事宜**：只读表格；"查看"→ `renderForm(instanceId, taskId, nodeKey)` 以 `readonly` 模式打开 `ApprovalPage`；"日志"→ `getLogs` 时间线。
- **我的请求**：`ProTable`（我的发起）；"进度"→ 流程图 + `getLogs`；"撤回"→ `withdrawInstance`（仅运行中且当前节点为创建人时允许）；"终止"→ `stopInstance`。

### 3.3 审批承载页（复用，不新建）
`ApprovalPage.tsx` 已具备：渲染真实表单（`renderForm` 取 `layoutJson`/`dataJson`/`fieldPerms`/`detailPerms`）、E9 风格操作栏（由 `allowMenus` 决定按钮）、字段值驱动网关（提交时字段值作为流程变量下发）。本模块的"待办办理""已办查看"均直接复用它，**不要新建第二个审批页**。

## 5. 交互逻辑详述

### 5.1 新建流程
1. 进入 `/workflow/center/create`：`useRequest(() => listDefinitions(), { ... })` → `pickPayload` 拆包 → 按 `type` 分组展示（参考 `MENUS_OPTIONS` 字典风格）。
2. 顶部搜索框按 `name` 过滤；可选 `formType` 切换。
3. 点击某流程卡片 → `Modal`/`Drawer` 内调用 `renderFormPreview(defId, formId, nodeKey?)` 取 `layoutJson`+`fieldPerms`+`allowMenus`，复用 `FieldRenderer`（`src/pages/FormMode/FormView/components/FieldRenderer`）渲染可编辑表单。
4. 提交：`startInstance({ defId, formId, dataId?, variables: formData })`（`skipErrorHandler:true`，由页内 `try/catch` 提示）→ 成功跳 `/workflow/my-request` 并 `message.success('发起成功')`。
5. **约束**：所有 ID 保持字符串；富文本意见走 `RichTextEditor`，避免被 XSS 过滤。

### 5.2 待办事宜
1. `ProTable` 的 `request` 调 `listTodo(currentUser.userid)`（`pickPayload` 拆包）。
2. 行"办理"：`window.open('/formmode/approval/ApprovalPage?instanceId='+instanceId+'&taskId='+taskId)`（复用现有独立页，与 `config/routes.ts` 的 `layout:false` 一致）。
3. 行"转办/加签"：`Modal` + `PersonOrgPicker` 选人 → `forwardTask/addSignTask`。
4. 行"催办"：`urgeTask`（无需选人）。
5. 行"流程"：抽屉展示 `getLogs(instanceId)` 时间线。
6. 按钮权限：`const { buttons } = usePageButtons('todo')`，用 `<PermissionButton code="workflow_todo_approve" buttons={buttons}>` 包裹"办理"等。

### 5.3 已办事宜
1. `listDone(currentUser.userid)`。
2. "查看"：`renderForm(instanceId, taskId, nodeKey)` 以 `readonly=true` 打开 `ApprovalPage`。
3. "日志"：`getLogs` 时间线；无办理类按钮（`allowMenus` 在只读态不渲染提交/退回）。

### 5.4 我的请求
1. 调 `listMyRequests(currentUser.userid)`（**待后端新增**；过渡期可先复用 `monitorCount` + 实例列表占位）。
2. "进度"：流程图（节点高亮当前 `currentNode`）+ `getLogs` 时间线。
3. "撤回"：`withdrawInstance(instanceId, opinion)`（仅 `status===0` 且当前节点操作者为本人时允许，前端按 `status` 禁用按钮）。
4. "终止"：`stopInstance(instanceId)`（运行中可终止）。
5. "重新发起"：取该实例 `formId/defId` 跳回「新建流程」并预填。

## 6. 与现有前端用户系统集成方式（重点）

### 6.1 身份与上下文
- **取当前用户**：所有列表的 `assignee` 来自 `initialState.currentUser.userid`（`getInitialState` 已注入，登录后全局可读）。
  ```ts
  import { useModel } from '@umijs/max';
  const { initialState } = useModel('@@initialState');
  const userId = initialState?.currentUser?.userid;
  ```
- **展示**：顶栏头像 `AvatarDropdown` 已显示 `currentUser.name`；页面内"发起人/创建人"直接显示 `currentUser.name`。

### 6.2 权限控制（两级）
- **页面/菜单级**：`access.ts` 现有 `canUser = !!currentUser`；可在 `access()` 返回里追加 `canWorkflow: canUser && (角色/权限判断)`。菜单经由 `dynamicRoutes()` 下发，未授权菜单根本不会出现在 `patchClientRoutes` 的 `extraRoutes` 中，天然不可达。
- **按钮级**：列表页用 `usePageButtons('todo'|'done'|'myrequest'|'create')` 取到该页按钮数组，配合 `<PermissionButton code="..." buttons={buttons}>` 控制"办理/转办/撤回"等显隐。`dynamicButtons()` 在 `getInitialState` 阶段写入 localStorage，刷新即生效。

### 6.3 鉴权与错误处理（零额外开发）
- `requestErrorConfig.ts` 的拦截器已为所有请求自动附带 `blade-auth` 与 `Tenant-Id`，本模块 service 调用**无需手动带 token**。
- 401 自动 `removeAll()` + 跳 `/user/login`；业务异常经 `pickPayload` 后由 `errorThrower` 提取 `msg` 弹 `message.error`。
- 审批/发起等强交互接口建议传 `skipErrorHandler:true`（现有 service 已对 `runWorkflowTest` 等这么做），由页面 `try/catch` 统一提示，避免"请求层 + 页面"重复弹窗。

### 6.4 动态路由接入
- 组件严格放在 `src/pages/Workflow/{Center|Todo|Done|MyRequest}/{Create|Todo|Done|MyRequest}.tsx`。
- `Func.formatRoutePath` 会把菜单 `path`（如 `/workflow/todo`）转成 `./pages/Workflow/Todo/Todo.tsx`；路径末段若含 `view/mode` 等词需以 PascalCase 写（见项目既有坑位说明）。
- 懒加载失败时回退 `./pages/exception/404` 并 `message.error`，符合现有兜底策略。

### 6.5 布局与水印
- 4 页均走 `app.tsx#layout` 的 ProLayout，无需自建 `<Outlet/>` 容器；水印、SettingDrawer、Footer 自动套用。
- 待办角标：在 `AvatarDropdown` 或自定义顶栏组件里 `useRequest(() => monitorCount(userId))`，取 `data.todo` 渲染 `<Badge count={todo}/>`，点选跳 `/workflow/todo`。

## 7. 关键实现要点 / 风险清单

| 风险点 | 说明 | 对策 |
|---|---|---|
| 雪花 ID 精度 | `instanceId`/`taskId`/`defId` 为 19 位，转 `number` 会丢精度导致"实例不存在" | 全程 `string`；entity/VO 已 `@JsonSerialize(ToStringSerializer.class)`，前端绝不 `Number()` |
| 响应拆包 | service 返回形态可能为"载荷本身 / {data:载荷} / {data:{data:载荷}}" | 一律 `pickPayload(res)`，不写 `res.data` |
| 重复错误提示 | 请求层与页内各弹一条 | 强交互接口传 `skipErrorHandler:true` + 页内 `try/catch` |
| XSS 过滤 | 后端 XSS 会删请求体里的 HTML/XML | 本模块表单不含 BPMN XML；富文本意见走 `RichTextEditor`，不手动拼 HTML |
| 按钮权限刷新 | 登录后才写入 localStorage | 进入页面时 `usePageButtons` 从 localStorage 读；改权限需重新登录/刷新 |
| 动态路由路径大小写 | `Func.formatRoutePath` 先 toLowerCase 再 PascalCase 回替常用词 | 路径末段组件名用 PascalCase（如 `Create`/`MyRequest`） |
| 审批页复用 | 新建第二个审批页会与 `ApprovalPage` 行为漂移 | 待办/已办"办理/查看"统一复用 `ApprovalPage` |
