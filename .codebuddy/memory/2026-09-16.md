## 修复：画布「更改元素」后节点信息不生成
- 现象：用户任务用 bpmn-js「更改元素」换成 任务/发送任务/脚本任务/接收任务/手工任务/业务规则任务/调用活动 后，「节点信息」没有生成。
- 根因（双重）：
  1. 后端 `WfDefinitionServiceImpl.nodeTypeOf` 只认 Start/UserTask/End/中间·边界事件/ServiceTask，其余任务类型返回 null → `saveBpmn` 跳过该元素（既建不出节点），且旧节点因「不在 seenNodeKeys」被当作画布已删除而连带删除。
  2. 前端 `BpmnDesigner.NODE_TYPES` 缺这些 `$type` → 选中新元素时不被当作节点抛给父级。
- 关键事实（查 bpmn-js 17.11.1 源码确认）：`BpmnReplace.replaceElement` 内 `bpmnFactory.create(type)` 会**重新生成元素 id**；`ModdleCopy._copyId` 见 `ids.assigned(oldId)` 为真（旧元素仍占着）→ 拒绝复用 → 替换后 nodeKey **一定变化**，旧节点的 operators/字段权限/表单布局会随旧 key 被清理，新节点按画布类型重建。如需保留配置须做 id 迁移（本次未做）。
- 修复：
  - `nodeTypeOf` 补：CallActivity→6；Task 分支：Send/Script/BusinessRule→6、Receive→5、其余（Task/ManualTask）→1。
  - `defaultNodeName` 补对应中文默认名（等待/自动处理/审批）。
  - `NODE_TYPES` 补 `bpmn:Task/ManualTask/ReceiveTask/SendTask/ScriptTask/BusinessRuleTask/CallActivity`。
- 验证：`mvn -pl blade-service/blade-workflow compile "-Dmaven.compiler.proc=full"` → BUILD SUCCESS。

## 临时调试：把 bpmn-js 内置属性面板放出来
- 先在 `bpmnDesigner.css` 把 `.wf-props` 的 `display:none !important` 换成固定右侧浮层（`position:fixed;right:0;width:380px`）。用户反馈位置不对，要求「放到右侧信息栏那一列（红框）」，遂改为绝对定位覆盖右栏。
- 几何/约束（关键）：`.wf-props` 的父容器（画布区，BpmnDesigner 内 `position:relative;overflow:hidden;border:1px`）会裁掉溢出；右栏 `.wf-side-panel` 是它在 `.wf-flow-layout` 里的兄弟列（340px + 1px 左边框）。故用 `div:has(> .wf-props){overflow:visible!important}` 精准放开裁剪，再 `.wf-props{position:absolute;top:0;bottom:0;right:-342px;width:340px;z-index:20}` → 正好盖住右栏。`:has()` 由父级无 class 无法用其他方式选中。
- 风险/回退：`overflow:visible` 只影响该画布区容器（画布本身 `absolute;inset:0` 不受影响）。**回退 = 删掉 `bpmnDesigner.css` 里 `div:has(> .wf-props)` + 新版 `.wf-props` 两条规则，恢复 `.wf-props{display:none!important}`**。当前处于「已放出来」的调试态，勿提交。
- CSS 改动走 HMR 自动生效，无需重启 8000。
- 追加：首次 `top:0` 把自定义栏「节点信息/出口信息」标题头挡住了 → 改为 `top:39px`（= `.wf-side-head` 高度：padding 8*2 + 标题行高 22 + 下边框 1），让标题头保留在内置面板之上。
- 再修：面板偏短/上方留白——因 `.wf-props` 定位父级是「画布容器」(被顶栏占高，比右栏矮一截)。改为让 `.wf-flow-layout` 成为定位基准：① `.wf-flow-layout{position:relative}`；② 画布容器 `div:has(> .wf-props){position:static!important}`（否则它仍是最近定位祖先）；③ `.wf-props` 的 `right` 由 `-342px` 改成 `0`（相对整列右缘，右栏宽 340 正好盖住内容区）。最终 `.wf-props{top:39;bottom:0;right:0;width:340}` = 精确盖住右栏 body。
- 用户又反馈：内置面板铺满整列把自定义「节点信息」正文挡住 → 改为**上下分屏**：右栏上半（标题头之下）给自定义 NodeDetail/LinkDetail，下半给内置面板。用 CSS 变量 `--dbg-split`（默认 50%）控制分界：`.wf-flow-layout{--dbg-split:50%}`、`.wf-side-body{height:calc(var(--dbg-split)-39px)}`、`.wf-props{top:var(--dbg-split);bottom:0}`。
