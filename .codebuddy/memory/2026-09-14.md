## 前端雪花 ID 精度丢失根因（重要）
- 现象：重新生成新版本 / 调 activate 报 400「流程定义不存在」或精度丢失。
- 真因：后端 saveAsNewVersion 返回 `R<String>`、activateVersion 收 `@PathVariable Long`，**后端链路不丢精度**；丢精度在**前端**：`WorkflowDesign.tsx` 两处 `activateVersion(Number(target.id))`(310，进入设计自动激活) 与 `activateVersion(Number(id))`(608，版本下拉切换) 把 19 位雪花 id 用 `Number()` 转数字，超 JS 安全整数(2^53)失真，后端收到失真 Long → selectById 查不到。
- 修复（前端文件不在 IDEA，直接改）：去掉两处 `Number()` 传字符串；`services/workflow/index.ts` 的 saveAsNewVersion/activateVersion/listVersions 参数类型 `number`→`string | number`。已改。
- 项目约定：**雪花 ID（defId 等）在前端任何 path 参数/比较都禁止 `Number()`，一律 String 处理**（实体已 ToStringSerializer）。注：`detailTable` 等处仍残留 `Number()`，后续如遇明细表精度问题同样处理。
