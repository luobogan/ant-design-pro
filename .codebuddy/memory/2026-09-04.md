- **现象**：①同一个字段可以重复拖入表格；②右键「只读/可编辑/必填」切了没效果。
- **根因①（属性不生效）**：上一轮为"保存样式"新增的 `loadLayoutData` 尾部
  `applyCellStyle(range, s)`，在 `setCellField`（上 fieldAttr 底色）**之后**又用保存的 `s` 整体覆盖，

- **根因②（重复拖动，同时也会导致属性失效）**：`saveLayoutData` 对「值不匹配」的字段格是
  `delete cellFieldMetaMap.current[key] + continue`（整格不保存）。
  而 `loadLayoutData` 开头会 `cellFieldMetaMap.current = {}` 清空再从 cellData 重建，
  → 该字段重载后元数据丢失 → 唯一性校验查不到（可重复拖入）、`resolveCellFieldId` 也查不到（属性失效）。

- **教训**：给「保存/还原样式」类改动时，必须确认**还原动作是否会覆盖由业务状态决定的样式**

## 修复：保存后刷新页面，同一字段仍可重复拖入（加载时序竞态）
- **现象**：保存 → 刷新页面 → 拖入同一字段仍成功（唯一性校验失效）；右键属性同样失效。
- **★ 根因（时序竞态 + 闭包过期）**：`UniverExcelGrid` 有**两处**加载布局：
  1. 主 effect（deps `[layoutData, workbook, sheetName, loadLayoutData]`）→ `setTimeout(loadLayoutData, 100)`
  2. **Univer 初始化 effect**（deps 仅 `[sheetName]`）→ `setTimeout(loadLayoutData, 300)`
  第 2 处是「只跑一次」的闭包，捕获的是 `layoutData` **初始值 `{}`**（真实布局是 `getFormLayout` 异步取回的），
  且判空用的是 `if (layoutData)` —— **`{}` 是 truthy**，于是调度了 `loadLayoutData({})`。
  而 `loadLayoutData` 开头会 `cellFieldMetaMap.current = {}` 并清空整表，
  **300ms 晚于 100ms**：真实数据先恢复（100ms），随后被空数据抹掉（300ms）→ 元数据全丢。
- **修复**：
  1. 新增 `layoutDataRef`（每次渲染同步最新值）+ `hasLayoutContent(data)`（区分「未加载的 `{}`」与
     「用户清空后保存的空布局」——后者有 `sheets`/`cellData` 键，必须加载才能清空表格）+ `resolveSheetData(data)`。
  2. 初始化处改为**在定时器触发时**读 `layoutDataRef.current`，空则跳过加载。
  3. 主 effect 同样用 `hasLayoutContent` 提前 return + 复用 `resolveSheetData`。
  4. 兜底：唯一性校验除内存 Map 外，再用 `collectPlacedFieldKeys(layoutDataRef.current)` 查持久化布局。
  5. `ExcelDesign.handleLayoutChange` 由「合并」`{...prev, ...data}` 改为**替换** `setLayoutData(data)`：
     合并会残留上一次的 `sheets`（过期），而解析时优先取 `sheets`，会把过期布局灌回表格
     （表现为"清空单元格后又自动恢复"）。
- **教训**：`if (layoutData)` 判空对 `{}` 无效（truthy！）；`loadLayoutData` 开头会清空元数据，
  任何"用可能为空的数据加载"的路径都必须用**内容判空**而不是对象判空。
  另外「只跑一次的初始化 effect」里读 props 会用 ref，否则必踩过期闭包。

## 修复：右键"粘贴"菜单项恒灰（Univer 剪贴板 Observable 发射顺序 bug）——已定位并修好
- **现象**：复制/剪切都正常、Ctrl+V 也能粘贴成功，唯独右键菜单里的「粘贴」按钮一直是灰色。
- **根因（Univer 自身 bug，非本项目代码）**：`menuClipboardDisabledObservable` 里发射顺序错了——
  ```js
  const subscription = lastCopyId$.subscribe((id) => { subscriber.next(!supportClipboard && !id); });
  subscriber.next(!supportClipboard);   // ← 这行在订阅之后
  ```
  `lastCopyId$` 是 BehaviorSubject，`subscribe()` 会**同步**吐出当前值：复制后 lastCopyId 非空，首帧算出正确的
  `!supportClipboard && !id === false`；但紧接着的 `subscriber.next(!supportClipboard)` 又把它覆盖成 `true`。
  于是只要 `supportClipboard === false`（`navigator.clipboard` 不可用 = 非 localhost/https 的非安全上下文），
  订阅结束时**最后一次发射恒为 true** → 粘贴永久灰；而之后只有"再复制一次"才会重新发射，所以菜单里永远灰。
  Ctrl+V 走命令不查菜单 `disabled$`，所以能用——这正是二者的矛盾来源。
  另：三个相关权限点（`WorksheetEditPermission`/`SetCellStyle`/`SetCellValue`）默认 `value = true`，故 d2 不是原因。
- **修复**：把 `subscriber.next(!supportClipboard)` 挪到订阅 `lastCopyId$` **之前**，让同步首帧的正确值成为最后一次发射。
- **最终改动 2 处**：
  1. `univer/packages/sheets-ui/src/menu/menu.ts`（**源码真源**——用户确认 Univer 源码就在 `univer/`）
  2. `ant-design-pro/src/univer-lib/sheets-ui/lib/es/index.js`（**运行时真正加载的文件**，

## 排查：复制/剪切后"粘贴"菜单项一直置灰（Univer 内部 disabled$ 机制）
- **机理**（`univerbak/packages/sheets-ui/src/menu/menu.ts` `PasteMenuItemFactory`）：
  `disabled$ = d1 || d2`
  - `d1 = menuClipboardDisabledObservable = !supportClipboard && !lastCopyId`
    - `supportClipboard = typeof navigator.clipboard !== 'undefined' && typeof navigator.clipboard.readText !== 'undefined'`
      （**非 localhost/https 的 http 环境下 `navigator.clipboard` 为 undefined → supportClipboard=false**）
    - 内部 `lastCopyId` 由 `sheets-ui/services/clipboard/clipboard.service.ts` 的 `copy()` **第 3 步**写入
      （`this._copyContentCache.set(copyId, ...)`，在写系统剪贴板之前）。
  - `d2 = getCurrentRangeDisable$(...)`，粘贴**独有**要求
    `WorksheetSetCellStylePermission` + `WorksheetSetCellValuePermission`
    （剪切只要求 Edit/Copy），故"复制/剪切能点、粘贴灰"正是缺这两项权限的特征。
- **关键陷阱**：`copy()` 在写内部缓存之前有两处提前 return —— `!selection`、`!copyContent`（`generateCopyContent` 返回 null）。
  若复制命令静默失败，`lastCopyId` 不会被写入 → 当 supportClipboard=false 时粘贴会**一直**置灰。
- **已加诊断**（UniverExcelGrid 的 clipboard effect）：
  - 初始化时打印 `[Clipboard] supportClipboard = ...`；
  - 注册 `fUniver.onCopy` 打印 `[Clipboard] CopyCommand 已执行（内部 copyId 应已写入）`。
- **判读**：supportClipboard=true → d1 恒 false，灰就是 d2 权限；supportClipboard=false 且未见"CopyCommand 已执行" → 复制命令失败导致无 copyId。
- 另：`beforeCommandExecuted` 仅通知、无法取消命令，故无法在命令层"阻止复制"。

## 修复：合并 Excel 单元格后保存，里面的文字消失
- **现象**：合并单元格 → 保存 → 合并格内的文字消失（实为合并本身在保存/刷新后丢失，文字错位看不见）。
- **根因（两处）**：
  1. **加载侧从不重应用合并**：`loadLayoutData` 只还原 `cellData` 值/样式/列宽行高，从不 `setMerge`；而保存会经 `onLayoutChange` 触发主 effect 重新 `loadLayoutData`，于是每次保存/刷新后合并全部丢失。
  2. **合并值落点**：Univer 合并语义是「只保留主格(左上角)的值」（`defaultMerge`），但某些合并路径不会把值移到主格；若主格为空、值落在非主格，重载重新合并(`defaultMerge`)后将以主格(空)显示 → 文字消失。
- **Univer 合并源码结论**（`packages/sheets/src/commands/commands/add-worksheet-merge.command.ts`）：
  - 合并走 `AddWorksheetMergeCommand`：若非主格有内容且 `defaultMerge` 为假 → 弹确认框；为真( facade `FRange.merge()` 默认) → 静默清除非主格、把范围内**第一个有值的格**移到主格(`getClearContentMutationParamsForRange`)。
  - facade：`FRange.merge({defaultMerge,isForceMerge})` / `FRange.breakApart()` / `FWorksheet.getMergeData()`；`getRange(row,col,numRows,numCols)` 四参签名。
- **修复**（`components/UniverExcelGrid.tsx`）：
  1. `loadLayoutData` 还原值/样式后、按 `data.mergedCells` 重应用合并：先 `getMergeData()` 遍历 `breakApart()` 清残留旧合并，再 `sheet.getRange(sr,sc,rs,cs).merge({defaultMerge:true})` 逐个重合并（try-catch 隔离）。
  2. `saveLayoutData` 在捕获 `mergedCells` 后做**值归一化**：若合并主格 `cellData[sr][sc]` 无值，则扫描该合并区域第一个有值的格，把其 `v` 归一到主格（纯数据层，不动工作表），确保重载重新合并后主格持有文字。
- 注：本文件有 16 个**预存** TS 错误（`@univerjs/*` 本地 file: 包无法解析），非本次引入；`ExcelPreview.tsx` 0 错误。改完 UniverExcelGrid 务必停 dev 重启 + 硬刷新（HMR 极不稳定）。

### 合并文字消失 · 二次修复（关键机制澄清）
- **源码级确认**：`FRange.merge()` → `addMergeCellsUtil` → 直接 `executeCommand(AddWorksheetMergeCommand)`，而该命令在 `willClearSomeCell` 为真时会用 `getClearContentMutationParamsForRanges` **清除非主格、只保留主格值**（不是 facade 另走的轻量路径）。所以"重新合并" = 只留主格值。
