# 2026-09-01

## 修复：ExcelDesign 拖动「字段」和「标签」未区分的问题

用户反馈：在 `ant-design-pro` 的 ExcelDesign 页面（formmode/exceldesign/ExcelDesign）
把字段面板的「标签」和「字段」拖到 Excel 后效果完全一样，没有区分。

### 根因（三处）
1. `UniverExcelGrid.tsx` 的 `handleFieldDrop`：resolvedType 只判断 `formField`，
   但后端字段都带 `fieldHtmlType`，导致标签也走了 `mapToFieldType`，两者 fieldType 相同。
2. `setCellField`：写入值都是 `图标 + fieldLabel`，显示完全一样。
3. `ExcelPreview` 的 `FieldCell` 按 `fieldType` 渲染输入控件，标签也被渲染成输入框。

### 修复（用户确认：字段用 `${字段名}` 占位符）
`UniverExcelGrid.tsx`：
- `FIELD_TYPE_META` 新增 `label` 类型（静态文本）
- `FieldMeta` 新增 `cellType?: 'label' | 'field'`
- `handleFieldDrop`：按 `type==='formLabel'` 判断，标签 fieldType 固定 `label` 并设 cellType
- `setCellField`：标签写标签文字；字段写 `图标 ${字段名}` 占位符
- `saveLayoutData` 值匹配验证：按 cellType 计算期望值（原逻辑只认 fieldLabel，
  会让占位符被判定为「值不匹配」而删除元数据、丢失字段！）；
  去图标正则放宽为 `\p{Extended_Pictographic}` 以覆盖 ☑️/⚙️ 等图标

`ExcelPreview.tsx`：
- `FieldMeta` 同步 cellType
- 标签单元格渲染为静态文字（不渲染输入控件）
- 预览取值识别 `${...}` 占位符并按空值处理，避免占位符成为输入框默认值

### 备注
- 属性面板通过 `getCellFieldMeta`（内存 Map）取元数据，不解析单元格文本，故不受影响。
- 仅剩预先存在的未使用变量 warning，无新增错误。

## 追加：字段占位符单元格禁止手动修改

用户要求拖入后的 `📝 ${xm}` 单元格禁止修改（手动改会破坏数据绑定，且保存时会被判为
「值不匹配」而丢失元数据）。

### 方案选择
Univer 有区域保护 API（`fWorksheet.getWorksheetPermission().protectRanges()`，见
`univer/packages/sheets/src/facade/permission/`），但内部依赖 `IAuthzIoService` 权限后端
（协作场景），本地单机设计器不可用 → 改用「监听变更 + 自动回滚」。

### 重构（消除三处重复逻辑）
抽出模块级公共函数（原逻辑分散在写入/保存校验，新增防篡改共三处）：
- `FIELD_ICON_MAP`：字段类型→图标前缀（从 setCellField 内部提到模块级）
- `getCellDisplayValue(meta)`：标签→标签文字，字段→`图标 ${字段名}`
- `stripFieldIcon(v)`：剥离图标前缀，用 `\p{Extended_Pictographic}` 覆盖 ☑️/⚙️
- `isCellValueMatchMeta(value, meta)`：值是否匹配（写入/保存/防篡改三处共用）

### 防篡改实现（onCellValueChange 回调内）
- 单元格有 fieldMeta（标签或字段）+ 新值非空 + 不在放置/回滚中 + 值不匹配
  → 还原为 `getCellDisplayValue(meta)` + `message.warning` 提示 + return 跳过保存
- **清空（Delete）允许** = 移除字段（走原有删除元数据逻辑），否则无法删除字段
- 新增 `isRestoringRef` 防止回滚的 setValue 再次触发变更事件导致递归

### 安全性验证
- 拖放覆盖：`handleFieldDrop` 先置 `isPlacingFieldRef=true` 再 setValue → 不误回滚
- 加载布局：`loadLayoutData` 先清空 meta(612) 再清空值(620)，且每格先存 meta 再 setValue
  → setValue 时 managedMeta 已是新 meta，匹配 → 不误回滚

## 修正：保护未生效的真正原因（重要）

用户反馈"该单元格由设计器管理，不可手动修改"没生效。

### 根因
**`FWorkbook` 根本没有 `onCellValueChange` 方法**！原代码 `fWorkbook.onCellValueChange?.(...)`
因可选链静默失效——不报错、不注册、永不回调。所以：
- 本次新增的防篡改逻辑从未执行
- 连原有的「清空单元格删除元数据」逻辑也一直是死代码

Facade 只有 3 个事件：`onBeforeCommandExecute` / `onCommandExecuted` / `onSelectionChange`。

### 为何不用前置拦截
`onBeforeCommandExecute` 内部是 `this._beforeCommandExecutionListeners.forEach(listener => listener(...))`
（command.service.ts:440），**返回值被忽略**，无法阻止命令，只能事后回滚。

### 最终实现
改用 `fWorkbook.onCommandExecuted`，过滤命令 id `'sheet.mutation.set-range-values'`：
- params: `{ unitId, subUnitId, cellValue: { [row]: { [col]: { v } } } }`
- `FRange.setValue` → SetRangeValuesCommand → 该 mutation，故手动编辑/程序写入都能捕获
- 遍历 cellValue 收集被篡改的单元格 → 循环**外**统一回滚（避免回滚触发递归）
- 额外加 subUnitId 校验，避免跨工作表误判

### 连带修复
新增 `isLoadingRef`：`loadLayoutData` 用 try/finally 包裹置位。
因为原事件是死代码，加载布局时从未触发过自动保存；一旦启用命令监听，
加载时的批量 setValue 会触发大量保存回调（可能导致 保存→重载→保存 循环），需屏蔽。

## 再修正：命令监听仍不生效 → 改用定时兜底

用户反馈改用 `onCommandExecuted` 后依然无效。

### 已排除的原因
- dist 与 src 均为最新（dist 里 `onCommandExecuted` 代码 + 新注释都在），不是没编译
- 命令 id `sheet.mutation.set-range-values` 确认存在于 Univer 0.25 源码
- 结论：Univer 单元格编辑器写回时**不走** SetRangeValuesMutation（Facade 事件覆盖不全）

### 最终方案：定时校验兜底（不依赖任何事件）
在 init 里加 `setInterval(800ms)`，扫描 `cellFieldMetaMap` 的每个受保护单元格：
- 用 `sheet.getRange(row,col).getValue()` 读当前值
- 空值 → 删除 meta（保留"清空=移除字段"）
- 与 `isCellValueMatchMeta` 不符 → 收集后循环外统一 setValue 还原 + message.warning
- 受 `isPlacingFieldRef` / `isRestoringRef` / `isLoadingRef` 三个标志保护
- cleanup 里 `clearInterval`（与 valueChangeDisposer 等一起）

**经验**：Univer 的事件/保护 API 都不可靠（Facade 事件少、前置拦不住、保护依赖后端），
这类"禁止修改"需求用轮询比对是唯一稳妥做法。

### 验证方式
控制台出现 `[Guard] 检测到设计器单元格被修改，自动还原:` 即表示兜底生效。
