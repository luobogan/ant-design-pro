# 2026-09-10 工作笔记

## 流程设计页 Bug 修复（前端 + 后端各一道）

### 1. 后端：wf_process_definition 列表查不出数据（两道关卡）
- 关卡①：TenantEntity 自动追加 `tenant_id=当前会话租户`，设计态模板数据在 000000 被过滤。修复：6 个"设计态"mapper 加 `@InterceptorIgnore(tenantLine="true")`（运行态表勿动）。
- 关卡②：tenant 去掉后 SQL 变 `where is_deleted=0 and (form_id = null)`——本项目 MyBatis-Plus 对 `.eq(列, null)` **不会忽略，原样拼成 `列 = null`**，SQL 恒 UNKNOWN → 0 行。修复：`WfDefinitionServiceImpl.listByForm` 改用 `.eq(formId != null, 列, formId)` 条件开关。
- 结论：GET /definition/list 返回全部数据（验证过 5 条）。

### 2. 前端：BpmnDesigner.tsx:86 `bpmnXml.trim is not a function`
- 根因（全局）：`ant-design-pro/src/requestErrorConfig.ts` 响应拦截器 `return response;`（umi 包装对象 `{data: ApiResponse, response, config...}`），umi-request **不会按泛型自动拆包**。导致 `request()` 返回的是包装对象，所有调用方 `r?.data` 拿到的是 `ApiResponse` 对象（多包一层），而非载荷。
  - 设计页：`bpmn = bpmnRes?.data` 拿到 ApiResponse 对象 → `.trim()` 抛错。
  - 列表页：`setDefs(r?.data || [])` 拿到对象而非数组 → 表格无数据（这也是"列表查不出"的前端一半原因）。
- 修复：响应拦截器改为 `return response.data;`（返回真正的 ApiResponse 体 `{code, success, data, msg}`），全站 `r.data`/`r.success` 语义立刻正确。
- 验证安全：扫描确认无调用方依赖包装对象的 `.headers/.config`（ImageUploader 的 `file.response` 是 Upload 组件属性，无关）。
- 注意：改的是请求实例配置，须**重启 8000 前端 dev server** 才生效。
- def 未保存过 BPMN 时 `bpmn` 为空 → 画布自动加载 STARTER_XML 初始模板，符合预期。
