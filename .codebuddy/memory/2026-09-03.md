## 修复：右键切「可编辑」报「没有字段元数据」（坐标错位真因）
- 真因（最终纠正，前两次归因都错）：**两套坐标约定冲突**，不是 hitTest 不存在、也不是它单纯偏一列。
  - Univer 的 `hitTest`/`getCellRect`/`getCellByOffset` 走**含表头偏移**坐标（列号比实际小 1），
    实测右键点视觉 `(1,1)` 的格子算出 `(1,0)`。
  - 本应用**拖拽落点写字段**用的是 `getCellFromMouseEvent` 的「列宽/行高累加、不含偏移」约定，
    元数据存的是这套列号（`'1_1'`）。
  - 曾把读取主路径换成 `getCellRect`/`hitTest`（另一套约定）→ 读 `(1,0)` 查不到 `'1_1'`。
  - 佐证：`hitTest`/`getCellRect`/`getSkeleton` 同属 `FWorksheet` 类（facade.js 922/934/1005），
    故 `getCellRect` 必然可用；日志 `hitTest 兜底 (1,0)` 说明落到了另一套约定。
- 修复：`getCellFromMouseEvent` **只用「列宽/行高累加、不含偏移」**（与写入完全一致），
  去掉 `getCellRect`/`hitTest` 主路径；删掉「实时鼠标位置」候选（点菜单时鼠标在菜单上会误伤别的字段）；
  字段属性/清空事件候选只剩 `rightClickCellRef → selection`，且取第一个有元数据的坐标。

## 坐标定位第 4 次迭代：手算还原也不对，转为「拿数据」而非再猜

  而此前 `hitTest` 给的是 **`(1,0)`**（行对、列差 1）。三种方法三种结果 → 不能再靠推断。
- 已确认：`hitTest` 与 `getCellRect`/`getSkeleton` 同属 `FWorksheet` 类（facade.js 922/934/1005），

- 另外确认：右键**不会**移动 Univer 选区（若会移动，selection 候选就该命中 `1_1`，实际没有），
  所以 `getSelection()` 只能当兜底、不能用。
- 当前做法：在 `handleContextMenuCapture` 加一次性诊断 `[CtxMenuDiag]`，右键时输出
  client/rel 坐标、canvasRect、列宽行高、handCalc、hitTest、各字段格 `getCellRect`、
  字段格实际 `getValue()`、以及 `fieldKeys`。据此一次定死映射。

## 第 5 次迭代：手算改坏了拖拽落点 → 还原 hitTest，并加「像素吸附」兜底
- 新症状：改成手算后**拖拽落点也错了**（用户反馈"拖进去不是想要的单元格"）。
- 决定性证据（终于找到，来自代码本身，非猜测）：
  1. 本文件 349-350 行（hover 高亮，未被我改动的原始代码）注释写明：
     `getCellRect` 是"**最精准**"方式（Skeleton 计算，含滚动/缩放/合并单元格），
     而「列宽/行高累加」被明确定性为 **"不可靠，仅作兜底"**——它不含表头偏移、
     不考虑滚动与缩放，这正是落点错位的原因。
  2. 拖拽处理自身残留 `// 方案1：使用 hitTest（最精准）` 与 `source = hitTest(${row},${col})`
     （约 1198-1206 行）→ **原始 getCellFromMouseEvent 就是 hitTest 主路径**，
     是我这次把它改掉才导致落点错位。
- 修复：
  1. `getCellFromMouseEvent` 还原为 **hitTest 主路径**（走 skeleton.getCellByOffset，
     与 Univer 自身点击选区判定同源，已处理滚动/缩放/表头偏移/合并单元格），
     「列宽/行高累加」降为 hitTest 不可用时的兜底。
  2. 新增 `rightClickPosRef`：缓存右键**瞬间**的鼠标 client 坐标
     （菜单项回调时鼠标已移到菜单上，不能用实时位置反算）。
  3. 新增 `findFieldCellByPosition()`：按索引查不到元数据时，改用**几何**判定——
     遍历已挂元数据的字段格，用 `getCellRect` 找包含右键点的那一格。
     与索引约定无关，即使落点/读取约定漂移也能命中用户实际看到的格子。
  4. `univer-field-attr-change` 与 `univer-cell-clear` 均接入该兜底（来源标记 `rectSnap`）。
