# 2026-09-02

## ExcelDesign：字段占位符单元格增加「灰色锁定」视觉

承接 2026-09-01 的工作（字段/标签区分 + 禁止手动修改）。
用户要求把拖入的 `📝 ${xm}` 单元格设成"灰色不能点击动的"。

### 实现
`UniverExcelGrid.tsx`：
- 模块级新增样式常量 `LOCKED_CELL_BG = '#f0f0f0'`、`LOCKED_CELL_FONT = '#8c8c8c'`
- `setCellField` 启用此前被注释掉的样式代码（原 TODO 写着"等待确认正确 API"）：
  仅对 `cellType === 'field'`（数据绑定占位符）设置灰底 + 灰字；
  标签（cellType='label'）保持默认样式，因为它视觉上等同普通说明文字
- `clearCell` 清空时恢复白底黑字，避免删除字段后残留灰底

## 追加：标签改为「允许修改」

用户反馈"字段标签 的可以改"——即标签（label）单元格应能自由改文字，
只有数据绑定的字段占位符才锁定。（此前我把标签和字段一并保护了，标签也被回滚，不符合预期。）

### 三处配套修改（缺一不可）
1. 轮询兜底：加 `if (meta.cellType !== 'field') return;`，标签不做保护
2. 命令监听（onCommandExecuted）：同样只对 field 回滚，标签放行
3. **`saveLayoutData` 校验（最关键）**：标签值不匹配时，同步 `fieldMeta.fieldLabel = 新值`
   并正常保存；**不能**沿用字段的"删除元数据 + continue"逻辑，
   否则标签一改就被当成过期元数据删掉，单元格内容丢失。
   （`getCellFieldMeta` 返回的是 Map 的引用，直接改 fieldMeta 即生效）

### 设计约定（最终）
| 类型 | cellType | 可改文字 | 视觉 | 清空 |
|------|----------|---------|------|------|
| 字段占位符 `📝 ${xm}` | field | 否（改了自动还原） | 灰底灰字（锁定） | 移除字段 |
| 标签「姓名」 | label | 是（同步 fieldLabel） | 默认样式 | 移除标签 |

## 追加：同一个字段只能拖入一次

用户要求主表/明细表中的同一个字段（标签/字段占位符）拖到 Excel 后不能再拖第二次。

### 核心实现：动态判断，不维护额外状态
`handleFieldDrop` 开头加唯一性校验，遍历 `cellFieldMetaMap` 检查
`${fieldId}_${cellType}` 是否已存在，已存在则 `message.warning` 并 return。

**为什么用动态判断而非维护 usedSet**：
- 清空单元格（移除字段）后自动释放，可再次拖入
- 刷新页面/加载布局后自动保持正确，无需持久化

### 面板置灰（视觉提前提示）
- `ExcelDesign.tsx`：`useMemo` 从 `layoutData` 的 cellData 提取
  `usedFieldKeys`（key = `${fieldId}_${cellType}`），传给 FieldPalette
- `FieldPalette.tsx`：`DraggableLabelItem` / `DraggableFieldOnlyItem` 新增 `disabled` prop
  → `useDrag` 的 `canDrag: !disabled` + 置灰样式（opacity 0.4 / not-allowed / 灰色文字）
  → 已拖入时 `ref` 不绑定 dragRef（彻底不可拖）

### 关键验证
拖放有两条路径，但**最终都调用 `handleFieldDrop`**，故校验对两者都生效：
1. react-dnd 的 `useDrop`（UniverExcelGrid 的 dropRef）
2. Univer 原生 `Event.Drop`（ExcelDesign.tsx 579 行调用 univerGrid.handleFieldDrop）

## 修复：保存布局报 `Range is out of bounds`

用户点保存报错：
```
Range is out of bounds. Max rows: 100, Max columns: 22,
Given range: {"startRow":0,"endRow":0,"startColumn":22,...}
at saveLayoutData (UniverExcelGrid.tsx:720)
```

### 根因
`saveLayoutData` 硬编码遍历 `maxRow=50, maxCol=26`，但当前工作表实际只有 **22 列**
（100 行）。访问第 23 列（index 22）时 `sheet.getRange(row, 22)` 抛越界异常，整个保存中断。

### 修复（两处硬编码 + 一层兜底）
1. `saveLayoutData`：改用 `sheet.getMaxRows()` / `getMaxColumns()` 动态取行列数
   （`Math.min` 限制上限 200 行 / 50 列，避免遍历过大）
2. `loadLayoutData` 的清空循环：同样硬编码 50×26，一并改为动态获取
3. 保存时读取单元格包 `try/catch`，单个单元格异常不再中断整个保存

### 经验
- Univer 的 `getRange` 越界会**抛异常**（不是返回 null），遍历单元格必须按实际行列数
- 行列数用 `FWorksheet.getMaxRows()` / `getMaxColumns()`；
  另有 `getLastRow()` / `getLastColumn()` 返回有内容的最后行列（不适合全量扫描）

### 当前语义
标签与字段占位符**各自独立计数**：「姓名」标签可拖一次，`${xm}` 字段也可拖一次。
（若用户要"一个字段总共只能拖一次"，把 key 改成只用 fieldId 即可。）

### 关于「不能点击动」的说明（已与用户确认需要说明的局限）
Univer 无法真正禁止选中/点击单元格：
- 区域保护 API（`getWorksheetPermission().protectRanges()`）依赖 `IAuthzIoService` 协作后端
- `onBeforeCommandExecute` 的返回值被忽略，无法前置拦截命令

且**单元格必须保持可选中**——右侧 PropertyPanel 要靠选中单元格来配置字段属性。
因此采用：灰色视觉（标识锁定）+ 内容保护（轮询兜底自动还原）。
用户仍可点选（用于配置属性），但内容改不动。

## 明确：只读/可编辑/必填 是"真实表单"语义标记（参照 ecology viewAttr）

用户澄清：右键「只读/可编辑/必填」不是设计器视觉游戏，而是标记该字段在**真实表单界面**是只读/可编辑/必填。
ecology 模型（`fieldAttrMap[fieldid]` / `viewAttr`）：`1=只读(禁用输入)`、`2=可编辑`、`3=必填(可输入+红*+提交校验非空)`，
对应本项目 `FieldMeta.fieldAttr`(1/2/3)，`setFieldAttr` 已派生 `readonly=attr===1`、`required=attr===3` 作单一数据源。

### 决策：ExcelPreview 即"真实表单"呈现（不另建运行时）
用户选择「在原基础上完善」——把现有 `ExcelPreview` 当作表单呈现来完善。

### ExcelPreview.tsx 改造
- 由 `defaultValue` 非受控改为**受控**：`formValues`（按 `${sheetId}__${row}__${col}` 记录）+ `onChange`
- `fieldAttr=1` → 控件 `disabled`；`fieldAttr=2` → 正常；`fieldAttr=3` → 红色 `*` + **「提交校验」按钮**
- 提交校验：遍历所有 `cellType==='field' && required` 字段，值为空则红框 + 「该项为必填」提示 + `message.error` 统计；
  checkbox 必填需勾选（`isEmptyValue` 对 checkbox 取 `!v`），其余按 undefined/null/''/空数组判空
- 注意：项目有两套表单体系——`FormView`(DataAdd/DataEdit) 走 `FieldDefinition` 体系，与 Excel 布局 fieldAttr 未打通；
  Excel 布局的 fieldAttr 目前仅被 ExcelPreview 消费（本次即在此落地语义）

## 右击菜单选择后：字段前面图标随 fieldAttr 切换

用户要求：右击「只读/可编辑/必填」选中后，字段**前面的图标**改成相应图标（不是只改背景色）。

### 实现（UniverExcelGrid.tsx）
- `getCellDisplayValue`：字段显示值 = `属性图标 + 类型图标 + ${字段名}`；
  属性图标 `attrIcon = fieldAttr===1 ? '🔒' : fieldAttr===3 ? '⚠️' : ''`（2=可编辑不加前缀，沿用类型图标）；
  `iconPart = [attrIcon, typeIcon].filter(Boolean).join(' ')`
- `setFieldAttr` 末尾 `range.setValue(getCellDisplayValue(fieldMeta))`：选中后立即改写单元格显示值，图标即时切换
- `stripFieldIcon` 贪婪正则 `^[\p{Extended_Pictographic}\uFE0F\s]+` 本就能剥离多个前导 emoji，
  故保存校验 `isCellValueMatchMeta` 与防篡改轮询不会因多一个图标而误判/误还原（✅ 已验证）
- 加载布局时 `getCellDisplayValue` 以持久化的 fieldAttr 为唯一数据源，图标自动还原
- 示例：`🔒 📝 ${xm}`(只读) / `📝 ${xm}`(可编辑) / `⚠️ 📝 ${xm}`(必填)

## 修复：选「只读」后能设，但切不回「可编辑/必填」(B 类)

用户确认现象：右击选「只读」单元格会变灰/出 🔒，但再右击同一格选「可编辑/必填」切不回去。

### 排查结论：不是 setFieldAttr 逻辑问题
- `setFieldAttr(row,col,attr)`、`isCellValueMatchMeta`、防篡改轮询、onCommandExecuted 轮询全部静态走查：
  切换时 `fieldMeta` 与 `cellFieldMetaMap` 是同一引用，`fieldAttr` 同步更新，轮询/还原用最新 meta，不会锁回只读。
- `handleLayoutChange` 只 `setLayoutData`，`loadLayoutData` 在 init effect（`initRef` 守卫）只跑一次，切换不触发 reload。
- 逻辑上切换本应生效 → 根因是**目标单元格取错（定位）**。

### 根因：活动选区漂移导致命中旧格
`onContextMenuCapture` 用 `getSelection()` 拿目标单元格，取的是**活动选区**而非鼠标所在格。
两次右键之间只要选区漂移（点了工具栏按钮/其它单元格），"切换"就作用到旧选区，
只读单元格本身没被改 → 表现为"只读切不回去"。

### 修复：用 hitTest 按鼠标坐标精确命中
`import '@univerjs/sheets-ui/facade'` 把 `FWorksheet.hitTest(clientX, clientY)` 挂到原型
（pacage.json 中 `"./facade"` 入口指向 `./src/facade/index.ts` 源码，故运行时可用，无需 rebuild）。
`onContextMenuCapture` 改为：
```ts
const sheet = (window as any).__univerFAPI?.getActiveWorkbook?.()?.getActiveSheet?.();
const hit = sheet?.hitTest?.(e.clientX, e.clientY); // {row, column, ...}
// row=hit.row, col=hit.column；hitTest 失败则兜底 getSelection()
```
`window.__univerFAPI = fUniver` 在 init 时已暴露（见文件 1355 行附近，该处原就有打印 `sheet.hitTest` 类型的调试日志）。
`ctxMenu.row/col` 现在来自 hitTest，ContextMenu 的 `cellInfo` 与 `onFieldAttrChange` 一并正确。
（`getSelection` 仅作兜底，hitTest 不可用时无回归。）

### 经验（Univer 命中测试）
- `FWorksheet.hitTest(x, y)` 入参是**视口坐标**（`e.clientX/clientY`），内部处理画布偏移/滚动/缩放，返回 `{row, column, left, top, width, height}`。
- 比直接碰 DI 拿 `SelectionRenderService`/`getCellWithCoordByOffset` 安全得多。
- 注意：右键菜单的 `e.stopPropagation()` 会阻断 Univer 原生右键逻辑，但**不能依赖右键改活动选区来定位目标单元格**。

### 更正：用户实际场景（同格先只读再可编辑）的根因是「reload 把可编辑格也刷灰」
用户追问："点完只读然后再点可编辑 没有相应的改成可编辑的图标来"——即**同一格、选区未漂移**，
所以定位（hitTest）不是主因。真正的根因在 `setCellField` + 1731 行的 `useEffect([layoutData])` 全量 reload：

链路：
1. 点「可编辑」→ `setFieldAttr(2)` 把格设成白底 + `📝 ${xm}`（🔒 已正确去掉，**图标逻辑没问题**）。
2. `setFieldAttr` 末尾 `onLayoutChange` → `setLayoutData` → 1731 的 `useEffect([layoutData])` 触发 →
   100ms 后 `loadLayoutData` 全量重载（先清空所有格再逐格 `setCellField`）。
3. **`setCellField` 对 `cellType==='field'` 无条件套灰色锁定样式**，无视 `fieldAttr`，
   于是可编辑格又被刷成灰底灰字。

结果：只读=灰底+🔒，可编辑=灰底+无🔒——**底色一模一样**，用户看到"切不回去"（🔒 其实已去掉，但灰底让人误以为还是只读）。

#### 修复（setCellField.tsx 568 起）
`setCellField` 的样式分支改为按 `fieldAttr` 上色，与 `setFieldAttr` 一致：
```
fieldAttr===1 → 灰底灰字(#f5f5f5/#999999)   // 只读
fieldAttr===3 → 浅红底(#fff1f0)               // 必填
fieldAttr===2 → 白底黑字(#ffffff/#000000)    // 可编辑，与只读明显区分
其它/未设置   → 默认灰底（保留占位符锁定观感，新拖入字段仍灰）
```
这样可编辑=白底、只读=灰底，视觉区分清晰，"切不回去"消除。

#### 关键认知
- `setFieldAttr` 会触发全量 reload（因为走 `onLayoutChange`→`setLayoutData`→`useEffect([layoutData])`）。
- 因此**任何只改 `setFieldAttr` 的样式而不改 `setCellField` 的做法都会被 reload 覆盖**——两处样式必须同步。
- 同理，若以后改"字段占位符视觉"，要同时改 `setFieldAttr` 和 `setCellField` 两处。
- 本次顺带的两处修复（`onContextMenuCapture` 用 hitTest 定位 + `setCellField` 按 fieldAttr 上色）互相独立、互不冲突。
