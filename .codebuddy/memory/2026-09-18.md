## 流程设计器：基础设置回显不出来（已发布/显示顺序/对应表单）
- 现象：基础设置里设好 已发布(status)/显示顺序(sortOrder)/对应表单(formId) 后保存，表单停在保存前旧值。
- 根因：`WorkflowDefForm` 值回填只在依赖 `[isEdit, initialValues?.id, form]` 的 effect 跑一次；保存后 `setFormRefresh` 按 `key=id-formRefresh` 重挂载组件、`reloadCurrent` 更新 current（initialValues 引用变），因只盯 id 不变 effect 不重跑 → 用旧值回显。
- 修复：拆分「字段加载」（依赖 id）与「值回填」（依赖 `fields` + `initialValues`）两个 effect，后者变化时都重跑 `resetFields()+setFieldsValue(buildInitialValues(...))`。
- 注：`status` 无独立列，靠继承 `BaseEntity.status` 持久化（0草稿/1已发布/2停用）。

## 流程测试页：/form/render 400「流程实例不存在」——前端 Number() 使雪花ID丢精度
- 现象：重启后端后 instId 能回传了，但 `/form/render?instanceId=...&nodeKey=...` 返回 400「流程实例不存在」（带不带 nodeKey 一样）。
- 根因：真实 instId=`2100969845358092291`，前端 `Number(result.instId)` 变成 `2100969845358092300`（末三位 291→300）→ 查不到实例。
  后端 `WfTestResultVO.instId` 特意用 `@JsonSerialize(using=ToStringSerializer)` 转字符串下发就是防这个，前端却转回了 number。
- 修复（全链路保持字符串）：
  - `services/workflow/index.ts`：`renderForm(instanceId: string | number, ...)`。
  - `ApprovalFormRender.tsx`：`ApprovalFormRenderProps.instanceId: string | number`。
  - `Test.tsx`：`instanceId={result.instId}`（去掉 `Number()`）。
  - 同类隐患一并修：`ExcelPreviewPage.tsx` `const instanceId = params.instanceId`、`ApprovalPage.tsx` `renderForm(instanceId, tid)`（两者原本都是 `Number(...)`）。
- 验证：用正确 ID 调 `/form/render` → 200，`nodeKey` 生效、`layoutJson` 有值；不带 nodeKey 时回的 nodeKey 为空（实例已跑到归档），印证 nodeKey 入参必需。
