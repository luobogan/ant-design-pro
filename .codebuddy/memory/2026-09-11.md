## 「点击节点不显示节点信息」——展示态被 pointer-events 屏蔽（已修）
- 现象：`/formmode/workflowdesign?defId=...` 里点画布节点，右侧「节点信息」不联动。
- 根因：`BpmnDesigner` 的 `editMode` **默认 false（只读展示态）**，`bpmnDesigner.css` 里 `.wf-designer-view .djs-container,\n.wf-designer-view .djs-container * { pointer-events: none !important }` 把整个画布屏蔽 → bpmn-js 的 `selection.changed` 根本不触发 → 只有 `.djs-overlay`（CSS 里唯一的例外，`pointer-events:auto`）上的「≡/➤」图标可点。这是双态设计的预期行为，不是 bug。
- 修法（保持只读语义，不动 pointer-events 规则）：用叠加层承载「点节点本体」。
  - `BpmnDesigner.tsx` 新增 `mkHit(w,h,onClick)`：透明 div，尺寸取节点 `width/height`（**图坐标系**）。
  - `renderOverlays()` 里 `const viewMode = !editModeRef.current;` → 展示态对每个节点先 add `type:'wf-node-hit'`、`position:{left:0,top:0}`、**`scale:true`** 的热区，再 add 原来的 `wf-node`（≡ 按钮，`scale:false` 固定 18px）。编辑态不铺热区，避免挡原生拖拽。同时补 `overlays.remove({type:'wf-node-hit'})`。
  - `useEffect([editMode])` 内补 `renderOverlaysRef.current?.()`（双态切换必须重建叠加层，否则热区不增删）。
  - `WorkflowDesign.tsx` 的 `onSelectNode` 增加 `if (k) setFlowSubTab('node')`（画布只出现在「流转设置」页签内，故无需动 `activeTab`）。
  - `NodeInfoPanel` 空态提示改为「可直接点击画布中的节点本体或节点上的「≡」」。
- 💡 diagram-js overlay 的 `scale` 语义（14.11.3 实测）：`Overlays._updateOverlayScale` 对 `scale === true` **不加任何 counter-transform** → 叠加层跟随 overlayRoot 的 `scale(zoom)`，即**随图缩放**；`scale: false` 会乘 `1/zoom` 反向缩放 → **屏幕尺寸恒定**。所以要"尺寸正好等于节点"用 `scale:true` + 图坐标系宽高。

## ❗ 修两个缺陷：新增只能点一次 + 表格宽高不自适应（2026-09-11）
- **缺陷1「点一次后再点不动」两个根因**：
  1. `seq` 用 `Date.now()`，而 BpmnDesigner 的 effect 依赖 `[createNodesEvt?.seq]` → 值不变 effect 不重跑。**改为父级自增计数器** `createSeqRef` + `fireCreateNodes(list)`（`onCreateNode` 与 `applyBatchNodes` 都走它）。
  2. 「新增节点」按钮放在 `Table.footer`，且 `draftRow` 非空时 footer 传 `undefined` → 草稿行一旦没清掉，按钮**整个消失**，用户就再也点不到。**改为表格下方的常驻 Button**（`disabled={!!draftRow}`），并在 `commitDraft` 里**先 `setDraftRow(null)` 再 `onCreateNode`**，保证创建失败也不会残留草稿。
  - 另在 BpmnDesigner 加 `lastCreateSeqRef`：同一 seq 只处理一次（防 StrictMode 重入/重复建形状）。
- **缺陷2 宽高自适应**：
  - `NODE_BOX` 去掉 `maxWidth:1400` 硬上限 → `width:'100%'` 撑满容器；列宽保留 + `scroll.x='max-content'` 横向滚动。
  - 新增 `bodyH` 状态：`window.innerHeight*0.52`（下限 220），监听 `resize`；`scroll={{x:'max-content', y: bodyH}}` → 表头吸顶 + 表体内部纵向滚动（`y` 是 max-height，内容少时自动收缩=也自适应内容）。
  - ⚠️ **不要测量父容器高度**：外层是 `maxHeight` 而非固定高度，测量会随表格内容变化形成 ResizeObserver 自反馈（表越长→可用高越大→表更长）。用窗口高度才稳定。

## ❗❗ 头号坑：展示态会**静默吃掉**画布建模命令（2026-09-11，务必记住）
- 现象：代码里调 `modeling.createShape / connect / removeElements`，**不报错但形状就是建不出来**（或只建出一部分）。
- 根因：`BpmnDesigner` 在 eventBus 上注册了 `commandStack.<action>.canExecute`（优先级 2000），只读态（`!editModeRef.current`）返回 `false` 阻断，覆盖 `shape.create / connection.create / elements.delete / shape.delete` 等。diagram-js 对 canExecute=false 是**静默跳过**（不抛异常），所以 try/catch 完全抓不到。
- 修法：任何程序化建模前**必须先** `editModeRef.current = true; setEditMode(true);`，放在 try 的最前面，不能放在建模之后。原实现就写在了后面 → 展示态下新增节点全被吞掉。
- 排查同类问题：先在画布点「编辑」进编辑态再试；若编辑态正常、展示态不正常，100% 是这个拦截。
