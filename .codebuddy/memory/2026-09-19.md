## 修复：必填「已经填了还提示未填」+「一次提交弹两条相同提示」
- 现象：`flow_mu6qi6bgutt2` 测试页已填 `字段4` 仍报「节点【开始】以下字段为必填： 字段4(field_4)」，且点一次提交弹**两条**一样的提示。

## 修复：「开始节点提交后 任务非待办状态，不可处理」（或签 + 全量循环办理 → 事务回滚）
- 现象：测试页在开始节点点提交 → 报「任务非待办状态，不可处理」→ 什么也没推进（库里 5 个实例的 3 条业务领导待办始终 `status=0`、实例 `status=0` 未推进）。
- 报错来源：`WfTaskServiceImpl.requireTodoTask`（`doApprove` 第一步就校验待办状态）。
- **根因**：`WfTestServiceImpl.step()` 原来 `for (WfTask t : todos)` **把实例的全部待办一次性办结**。而该节点 `extJson.sign=0` 是**或签**：`doApprove` 办结首条时走 `closeSiblings(instId, nodeKey, taskId)` 关闭同节点其余待办并推进引擎；循环接着办第 2、3 条时它们已非待办 → `requireTodoTask` 抛异常 → `step()` 是 `@Transactional` → **整笔回滚**，表现为「提交报错且什么都没发生」。
- 修复（`WfTestServiceImpl.step()`，共 3 点）：
  1. **只办当前节点**：`String curNodeKey = todos.get(0).getNodeKey();` + 循环内 `if (!curNodeKey.equals(t.getNodeKey())) continue;`（多节点并存时也逐节点推进）。
  2. **逐条复查状态**：办理前 `WfTask fresh = taskMapper.selectById(t.getId())`，非 TODO 直接 `continue`（或签被 closeSiblings 关闭的不再办理）→ 不再抛错回滚。会签(a)、依次(2) 仍按 `doApprove` 门禁语义由同一循环走完。
  3. **开始节点（申请人）表单提交不再推进引擎**：`fromStartNode = firstNode != null && firstNode.getNodeKey().equals(dto.formNodeKey) && todos 中无该节点待办` → 命中即只做「权限矩阵 + 布局必填校验 + 落快照」并返回 `state()`（summary 提示流程停在当前待办节点）。理由：开始节点在 `instanceService.start` 时已被 `advance()` 自动完成、不生成待办，引擎本就停在下一节点；若顺手办掉它，测试者就再无机会办理（就是本条 bug 的现象）。前端 `doStep` 会把 `viewNodeKey` 切到返回的 `currentNodeKey`，面板自动跳到该节点继续办理。
- 预期完整流程：开始节点填 `字段4` → 提交（只校验+存值，不推进）→ 面板自动切到业务领导 → 填 `test(tes)` → 提交 → 或签办结首条、关闭其余 2 条、推进到归档 → 测试结束。
- 验证：`mvn -o -pl blade-service/blade-workflow -am compile -DskipTests` BUILD SUCCESS。**需重启 WorkflowApplication**。
