## 修复：模拟日志在「经过网关」时误报「未找到连线」
- 现象：路径经过并行网关时日志出现 `3 → 1 未找到连线 / 走线失败`（画布上确实有线，只是形状是 `3 → 网关 → 1`）。
- 根因：`wf_node_link` 的出口是 `saveBpmn` **穿透网关折叠**后的逻辑出口（A→网关→B 记为 A→B，`viaGateway=1`，见 `WfDefinitionServiceImpl` L365-388），画布上并不存在 A→B 直连，故 `findConn(from,to)` 必然落空。
- 修法（`BpmnDesigner.tsx`）：新增 `findRoute(from,to)` —— 先试直连，失败则 BFS **穿透「非流程节点」的中转元素（网关/事件）** 还原真实路线（`nodeKeySet` 取自 `simulateEvt.nodes`，与后端「不越过中间业务节点」的折叠规则对齐）；动画改为**逐跳**点亮/走光点，日志逐跳输出（中间跳 extra=`网关中转`，末跳带 `conditionCn`），中转网关本身也 `wf-sim-node` 点亮。整条路都找不到才记「未找到连线」。
- 遗留同类问题（已修）：`focusEvt.link` 的直连匹配（`BpmnDesigner.tsx` 定位 effect）。新增 `findFlowThroughGateway`（先试直连 `c.target?.id===to || targetRef?.id===to`，再 BFS 穿透 Gateway 元素）→ 出口信息「定位」对 `viaGateway=1` 出口也能命中。✅ 顺带修了旧代码 `c.businessObject?.targetRef === to`（对象比字符串恒 false）的直连匹配 bug（此前直连出口定位其实也一直是坏的）。

## 修：中间/边界事件节点生成 + 编译报错（blade-workflow 模块）
- 需求/现象：画布追加「中间件(中间事件)/边界事件」后，节点信息与出口线条没同步生成；且 `mvn compile` 报 `IntermediateThrowEvent` 找不到 + `SimulateResultVO` 找不到。
- 根因①：后端 `WfDefinitionServiceImpl.nodeTypeOf()` 只认 Start/UserTask/End，中间/边界事件返回 null 被跳过。
- 根因②：flowable 7.1 的 `org.flowable.bpmn.model` **没有 `IntermediateThrowEvent` 类**（只有 `IntermediateCatchEvent` 与基类 `ThrowEvent`）；bpmn-js 的中间抛出事件在 flowable 解析为 `IntermediateCatchEvent` 或 `ThrowEvent`。原代码 import `IntermediateThrowEvent` → 编译失败。
- 根因③：`SimulateResultVO` 找不到是 api 模块 jar 没装进 CLI 用的 `~/.m2`（双仓库问题，旧 jar 缺这个类）。
- 修：① `nodeTypeOf` 把 `IntermediateCatchEvent || ThrowEvent || BoundaryEvent` → nodeType 5(等待)，`ServiceTask`→6(自动处理)，补默认名；② import 改 `ThrowEvent` 兜底抛事件；③ `mvn -pl blade-service-api/blade-workflow-api clean install -DskipTests -Dmaven.compiler.proc=full` 重装 api 到 `~/.m2`，并 Rename 让位把新 jar 复制到 `E:\project\mavenLib` 两处。重编译 `blade-service/blade-workflow` → BUILD SUCCESS。
- 前端 `BpmnDesigner.NODE_TYPES` 已补 4 个 `$type` 使选中事件联动右侧面板。

## 修：WorkflowApplication 启动报 `IFormmodeClient` bean not found
- 现象：`Parameter 9 of constructor in WfDefinitionServiceImpl required a bean of type 'org.springblade.formmode.feign.IFormmodeClient' that could not be found`（@RequiredArgsConstructor 共 10 参，0-based 第 9 个即 formmodeClient）。
- 排查（全部"看起来正常"）：`blade-workflow/pom.xml` 有 `blade-formmode-api`；`dependency:tree` 确认 `blade-formmode-api:5.0.1:compile` + `spring-cloud-starter-openfeign:5.0.2` + `blade-core-cloud:5.0.1` 均在 classpath；两个仓库的 jar 都含 `IFormmodeClient.class`（带 `@FeignClient(value="blade-formmode", fallback=...)`）与 `IFormmodeClientFallback.class`（带 `@Component`，字节码 65 与 IUserClient 一致）；`feign.sentinel.enabled=true`；启动类/pom 自 `a3f4f64` 后未改。
- 结论：类可加载却无 bean 定义 ⇒ 本次启动 **Feign 客户端注册未生效**（`@EnableFeignClients` 仅来自 `@BladeCloudApplication` 元注解）。
- 修：`WorkflowApplication` 显式加 `@EnableFeignClients(basePackages = {"org.springblade"})`（对齐 `SystemApplication` 的"预防性修复"写法；`@Import(FeignClientsRegistrar)` 在同一类上会被去重，不会重复注册）。重编译 BUILD SUCCESS。
- 若重启仍报同类错：用 `--debug` 取 ConditionEvaluationReport 里 Feign 相关项；或把 `IFormmodeClient` 改 `ObjectProvider` 可选注入（该调用本身是 best-effort，仅 warn 不回滚）。
