# 流程管理模块 — 开发计划（整合版）

> 整合 `流程管理模块实施计划` 与 `流程中心菜单驱动化`。

## 一、目标

在 ant-design-pro（`@umijs/max`）落地流程管理模块：用户侧 4 个页面（新建流程 / 待办事宜 / 已办事宜 / 我的请求），并把这些路由从静态写死改为由 `blade_menu` 菜单表驱动、受角色授权控制。

## 二、真实完成度（源文件 todos 全 completed）

| 子计划 | 内容 | 状态 |
| --- | --- | --- |
| 用户侧 4 页 | 补充 workflow service（MyRequestItem/listMyRequests/StartableWorkflow/TodoItem/DoneItem）、config/routes.ts 加 4 静态路由兜底、实现 Create/Todo/Done/Request 页面（复用 ApprovalPage + 动态路由/按钮权限/用户系统集成） | ✅（页面 Create/Done/Request/Todo 已存在于 Workflow/ 下） |
| 菜单驱动化 | blade_menu 迁移 SQL（流程中心父菜单 + 4 category=1 子页 + 3 category=2 按钮 + workflow 角色授权）、移动 Create 到 Workflow/Create、MyRequest 改名 Workflow/Request、对齐 `workflow_` 权限码、删除 routes.ts 静态块、验证四页经菜单可达且按钮权限生效 | ✅ |

## 三、关键约束（菜单驱动）

- `MenuServiceImpl.buildRoutes` 仅收 `category=1` 进路由树/侧边栏；`category=2` 仅按钮。
- 主菜单组件路径算法取 path 首段+末段：`/workflow/todo` → `./pages/Workflow/Todo/Todo.tsx`；三段会被错算，故「我的请求」改用 `/workflow/request`、文件 `Request/Request.tsx`。
- 按钮经 `getButton(code)` 按父菜单 code 取子按钮，页面 `usePageButtons` 的 code 须与菜单一致并授权给 `role_alias='workflow'`。
